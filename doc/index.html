Documentatie API Tradeville

v1.1 - 22feb21

Introducere

Scop

Tradeville pune la dispozitia clientilor un API in scop de reporting, exclusiv pentru uz personal. Prin API se pot accesa date atat cu privire la activitatea contului de tranzactionare (portofoliul curent, istoricul de tranzactionare), cat si date de piata (istoricul tranzactiilor, ultimele cotatii pe simbol etc.).

Din cauza contextului juridic, prin API nu se pot lansa in prezent ordine de tranzactionare. Aceasta functionalitate poate fi folosita in schimb pt conturile demo.

In vederea accesarii API Tradeville, trebuie semnat un Act Aditional la contractul Tradeville. Pentru acest lucru, va rugam sa apelati la departamentul Helpdesk printr-un email sau folosind chatul din platforma

Principii de implementare

API-ul Tradeville poate fi folosit pentru a raspunde la nevoi punctuale de reporting (spre exemplu, pentru extragerea datelor privind portofoliul la un moment in timp in vederea elaborarii unui raport personalizat de risc).

In acelasi timp, API Tradeville poate fi folosit drept mediu de comunicare in vederea constructiei unei interfete personalizate de monitorizare a pietei, actualizata cu ultimele cotatii live

Pentru a indeplini al doilea scop, a fost nevoie de o solutie care sa permita comunicarea bidirectionala intre Tradeville si "aplicatia client".
Un simplu REST API nu permite transmiterea actualizarilor de cotatii prin push de catre Tradeville fara existenta unui server ridicat de catre "aplicatia client" sau un gateway cu acelasi scop.
Drept urmare, API Tradeville se bazeaza in totalitate pe comunicarea prin Websocket , ce permite comunicarea bidirectionala cu cel mai mic nivel de efort/implementare/deployment din partea clientilor Tradeville.

Comunicarea se realizeaza prin mesaje JSON. In cadrul fiecarui raspuns primit exista o propietate ce contine datele in forma bruta. In cazul in care acestea au o structura tabelara (spre exemplu in cazul comenzii Portfolio) serializarea acestora este in cadrul unui obiect JSON ce are ca propietati "coloanele tabelului", iar drept valori are array-uri cu elementele propriu-zise ale "tabelului".
Acest format a fost ales pentru serializare (in locul unui array de obiecte) deoarece permite compactarea cea mai eficienta.

Principii de folosire

Etapele pentru accesarea API Tradeville (indiferent de limbaj) sunt urmatoarele:

  • Se deschide un websocket catre adresa wss://api.tradeville.ro:443, cu protocol "apitv". Modul in care se face acest lucru depinde de limbajul de programare folosit, insa fiecare limbaj are suport pentru conexiuni websocket (intr-un mod integrat, sau folosind pachete/module externe)
  • Se efectueaza autentificarea in mediul Tradeville, prin transmiterea unei comenzi de login
  • Ulterior autentificarii, se pot apela toate comenzile disponibile.

Pasul cel mai dificil este conectarea cu succes prin websocket. In caz de dificultati, verificati ca sunt specificate corect detaliile precum portul si protocolul indicat, respectiv ca sunt tratate corect evenimentele clasice aferente: onOpen, onClose, onMessage.
La finalul acestei documentatii sunt date cateva exemple practice de conectare, in mai multe limbaje de programare

In cazul constructiei unei aplicatii complexe de monitorizare a plietei, un aspect important este modul in care se implementeaza actualizarea cotatiilor.
Acest lucru trebuie facut prin utilizarea comenzii Subscribe (la lista de simboluri dorita). Spre exemplu, pentru afisarea portofoliului curent de actiuni actualizat cu ultimele cotatii:

  • initial trebuie apelata comanda Portfolio
  • ulterior salvarii datelor din raspuns, se va apela comanda Subscribe pentru lista de simboluri din portofoliu
  • din acel moment, se vor intercepta cotatiile noi primite, iar pe baza acestora se va actualiza portofoliul
O alta abordare (nerecomandata) este apelarea succesiva a comenzii Portfolio si exista o anumita limitare. Aceasta limitare este de "maxim 20 de comenzi in 10 secunde", iar daca se depaseste, raspunsul servit va contine un mesaj de eroare. Depasirea ocazionala nu ar trebui sa fie o problema pentru ca se reseteaza in maximum 20 de secunde. Depasirea frecventa va duce in schimb la activarea celorlalte protectii privind traficul, iar acolo nu putem sa dam detalii exacte privind limitele.

Transmiterea comenzilor catre API Tradeville se face prin trimiterea unui JSON (sub forma de string, prin websocket) cu doua propietati:

  • cmd: numele comenzii
  • prm: un obiect (JSON) ce contine parametri specifici comenzii respective
Raspunsul returnat de catre server va contine intotdeauna aceste doua propietati, in vederea asocierii comanda-raspuns.

Comanda login

Descriere : Efectueaza login si este obligatoriu sa se execute inaintea oricarei alte comenzi

Parametri acceptati:

Nume parametru Tip parametru Optional/Obligatoriu Descriere
coduser String Obligatoriu

Codul de utilizator din platforma Tradeville
parola String Obligatoriu

Parola aferenta contului
demo Boolean Obligatoriu

Este sau nu un cont demo (true/false)

Exemplu comanda: { "cmd ": "login ", "prm ": { "coduser ": "!DemoAPITDV ", "parola ": "DemoAPITDV ", "demo ": true } }

Raspuns prelucrat:

coduser parola demo raspuns
!DemoAPITDV DemoAPITDV true Ok

                                var WebSocket = require('websocket').w3cwebsocket;
            var fs = require('fs');
            var websocket;

            function startws() {
                websocket = new WebSocket("wss://api.tradeville.ro ", ["apitv "]);
                websocket.onopen = ()=>sendJS({cmd:'login',prm:{coduser:'!DemoAPITDV', parola:'DemoAPITDV', demo:true}});
                websocket.onerror = (err)=>console.log('eroare la conectare');
                websocket.onmessage = mesajAPI;
            }
            startws();

            function mesajAPI(evt) {
                var ce;
                try {ce=JSON.parse(evt.data)} catch (e) {}
                if(!ce) return;
                afiseaza(ce);
            }
            function sendJS(oo){
                if(websocket.readyState!=1) {afiseaza('fara conexiune la server'); return;}
                websocket.send(JSON.stringify(oo));
            }

            function afiseaza(ce={}){
                if(ce.prm) delete ce.prm.parola;
                if(ce.cmd=='Portfolio') {
                    fs.writeFileSync('portofoliu.csv', data2tabel(ce.data));
                    console.log('am creat/modificat fisierul portofoliu.csv');
                    process.exit();
                }
                console.log(ce);
                if(ce.cmd=='login') {
                    if(ce.OK) sendJS({cmd:'Portfolio',prm:{data:null}}); else process.exit();
                }
            }

            function data2tabel(dd){
                if(Array.isArray(dd)){let st='';dd.forEach(a=>st+=data2tabel(a)); return st;}
                let ss='', c1=dd[Object.keys(dd)[0]];
                for(let k in dd) ss+=(ss?',':'')+k;
                ss+='\r\n'; if(!Array.isArray(c1)) return c1;
                c1.forEach((r,i)=>{
                    let rr='';
                    for(let k in dd) rr+=(rr?',':'')+dd[k][i];
                    ss+=rr+'\r\n';
                });
                return ss;
            }

                    def send_and_recived_message(self, message):
                        self.ws.send(message)
                        print(f "Sent message: {message}.")
                        result = self.ws.recv()
                        print(f "Received: {result}.\n ")

                        self.ws.send(message)
                        print(f "Sent message: {message}.")

                        result = self.ws.recv()
